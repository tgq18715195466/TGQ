# 掌柜智库项目解析

## 1. 项目定位

掌柜智库管理企业文档从上传到可追踪回答的链路：文档版本、权限、解析质量、索引同步、问答证据与任务恢复。与同仓库 ERP 独立运行，不直接操作 ERP 库存和订单。

## 2. 模块与源码导航

- **API 与登录**：`app/api.py`、`password_auth.py`、`security.py`，负责认证、接口、文件访问与 SSE。
- **事实层**：`app/models.py`、`db.py`、`repository.py`、`alembic/`，负责租户数据、事务、权限和迁移。
- **导入**：`app/ingestion/` 处理文件校验、归一化、解析和结构切分；`ingest_runner.py` 持久化阶段结果。
- **检索问答**：`app/query.py` 编排三路召回；`keyword.py` 实现 BM25；`retrieval.py` 负责融合、上下文、证据和引用校验。
- **外部服务**：`app/adapters/` 对接模型、Milvus 和 Neo4j。
- **可靠性**：`app/workflows.py`、`worker.py`、`sync.py` 负责 checkpoint、任务重试、Outbox 和巡检。
- **工作台**：`web/src/pages/` 提供知识库、文档、问答、评测与系统状态页面。
- **验证**：`tests/`、`eval/`、`scripts/` 提供单元、数据库、可选真实外部集成和评测工具。

## 3. 两条主要数据流

### 文档导入

上传与幂等校验 → 保存文件和任务 → 扫描 / 格式校验 → PDF 归一化 → MinerU → 质量门 → 结构切分 → Embedding → Milvus → 实体关系抽取 → Neo4j → 收据检查 → 发布版本。

质量失败或必要同步未完成时不发布。模型和外部服务异常会形成可观察任务状态，不生成模拟成功结果。

### 检索问答

身份及知识库范围 → 问题分类 → 三路召回 → RRF → 授权回表 → reranker → 上下文选择 → 证据门 → 模型 → 引用校验 → 事务提交 → 持久 SSE。

事实问答采用严格摘录，总结 / 对比允许改写并核对数字。两者约束不同，不能把有引用等同于全文已被语义证明。

## 4. 关键工程选择

### PostgreSQL 作为事实源

原文件、规范化 PDF、正文、会话、任务与事件统一落库；Milvus 和 Neo4j 保存可重建的检索结构。代价是数据库及 WAL 随文件量增长，需要容量规划和恢复演练。

### Outbox 与发布门

片段与外部同步任务在同一事务写入，必要收据齐全才切换有效版本。删除等待外部补偿，硬删除进一步清理历史引用与事件快照。

### 检索全过程授权

租户 RLS、知识库成员关系、文档 ACL 与索引标量过滤共同约束候选；提交前重新授权并锁定文档，减少删除 / 取消与答案提交的竞态。

### 可重放的 SSE

浏览器消费已提交事件，断线可按序号恢复。答案生成和校验后才输出，首字延迟仍需实测。

### 可解释的基础检索

BM25 在授权语料上即时计算，图谱依赖显式实体和关系模式，便于测试和审计。海量语料性能、通用关系抽取仍需演进。

## 5. 当前成果与后续工作

源码覆盖多租户知识库、上传、持久导入、混合检索、引用、SSE、登录、React 工作台与评测框架；历史部署记录含真实服务适配验证。

待完善：真实业务评测集和 RAGAS、总结忠实度验证、规模性能、生产越权矩阵、SSO、恢复演练、在线模型迁移和外部搜索引用闭环。

演示时使用自有或获授权的小型文档，展示上传、处理阶段、READY、问答及引用，再用资料外问题演示证据不足。服务不可用时展示任务状态，不以 fixture 代替真实效果。
