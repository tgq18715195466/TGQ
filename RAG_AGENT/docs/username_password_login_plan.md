# 用户名密码登录实施方案（2026-09-30）

目标：保留现有双栏中文登录页，将访问令牌文本框改为用户名与密码输入。用户提交凭据后，后端验证密码并签发一小时 JWT；React 仅在 `/me` 验证成功后渲染工作台。问答、任务、文档等 API 继续由后端验证 JWT 与资源权限。

设计选择：以 PostgreSQL 中的独立登录凭据表关联现有租户和用户。用户名全局唯一；凭据表使用固定内部认证租户的 RLS 策略，业务用户与数据仍按原租户 RLS。密码用带随机盐的 PBKDF2-SHA256 哈希保存，登录失败给统一错误并在哈希前按来源限流；禁用用户不可登录。现有 `.runtime/demo.json` 用户由本地管理脚本设置 `admin` 登录名和随机初始密码，初始密码只写入被忽略的 `.runtime/local_login.txt`，不使用 PostgreSQL 密码。

实施顺序：
1. 先写密码校验和登录 API 的失败用例，覆盖正确/错误密码、未知用户、停用用户、锁定、未登录访问 Agent。
2. 增加凭据模型和 Alembic 0002；实现密码服务、登录端点、本地设置/重置命令。
3. 先写 React 登录表单测试，再替换输入框和请求流程；去掉 URL 令牌登录入口，保留本次浏览器会话中的登录状态。
4. 更新本地启动脚本、README、交付文档；迁移现有数据库，创建本地账号，运行前后端与浏览器验收。

边界：此方案提供本地用户名密码认证，不包含生产 SSO、多因素认证或面向用户的自助重置密码。生产部署仍需正式身份管理与统一限流策略。
