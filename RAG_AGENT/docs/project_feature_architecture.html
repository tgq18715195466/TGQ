01 · 四层架构

前端：交互与展示

React + TypeScript：登录、工作台、知识库、文档、问答、引用、评测和系统状态。负责请求提交与进度展示。

web/src/

后端：业务与权限

FastAPI + PostgreSQL：身份、数据范围、文件版本、持久任务、会话、事件、审计与幂等接口。

api.py / repository.py / models.py

Agent：工作流编排

LangGraph + Worker：执行阶段、并行召回、状态持久化、失败重试和索引补偿。

workflows.py / worker.py / query.py

RAG：知识处理

MinerU、BGE、Milvus、FTS、Neo4j 和 LLM：解析、切分、建索引、召回、融合、生成及校验。

ingestion/ / adapters/ / retrieval.py

四层是职责划分，不是四个独立部署服务。API 和 Worker 分进程运行；Agent 与 RAG 代码主要由 Worker 执行。

02 · 文档导入与结构化解析

  • 格式校验：扩展名、MIME、文件签名一致性；检查 PDF、图片、Office 容器，拒绝危险结构。
  • 恶意扫描：scanner shim 将原始文件交给 ClamAV，未明确扫描通过则不放行。
  • 文件归一化：pypdf 处理 PDF；Pillow 处理图片；ReportLab 将文本转 PDF；Office 转换依赖 LibreOffice。
  • MinerU 解析：调用 /file_parse，映射正文、标题、列表、表格、公式和图片相关文字，保存页码、块和资产。
  • 质量门：检查页数、空白内容、乱码与表格结构，输出 PASS / WARN / BLOCK；BLOCK 阻断建库。
  • 结构化切分：标题大纲、段落/句子边界、标题路径注入、表格行组处理及稳定 chunk ID，保留页码与来源块。
  • 双索引发布：向量写入 Milvus，规则抽取实体关系后同步 Neo4j；满足质量、非空 chunk 和同步完成条件才发布版本。

13 阶段业务链

validate_file → persist_document → normalize_file → parse_with_mineru
→ validate_parse_quality → build_outline → create_chunks
→ generate_embeddings → sync_milvus → extract_entities → sync_neo4j
→ publish_version → cleanup_temp_files

默认文件上限 50 MiB、500 页，是校验上限，不等于实测容量。切分配置虽以 token 命名，当前计数实际上采用 UTF-8 字节保守预算，并非模型真实分词器计数。

依据：app/ingestion/、app/ingest_runner.py、app/workflows.py。

03 · 三路召回检索（Triple Retrieval）

向量语义检索

  • BGE-M3 经 TEI 生成 1024 维向量。
  • Milvus HNSW 索引 + COSINE 相似度。
  • 默认 Top40，过滤租户、知识库、当前版本和 ACL。
  • collection 按模型与维度隔离。

关键词检索

  • jieba + 应用内 Okapi BM25。
  • 授权当前片段作为语料，计算词频、IDF 和平均长度。
  • BM25 排序，默认 Top30；k1=1.2，b=0.75。
  • 每次查询扫描授权语料；旧 FTS 索引保留但不参与召回。

知识图谱检索

  • Neo4j Entity / Alias 字符串匹配。
  • Cypher 关系路径最多 2 跳。
  • 回溯支撑 chunk，默认 Top30。
  • 逐边校验来源、租户、版本与权限。

Cross-Encoder 重排

  • BAAI/bge-reranker-v2-m3 经 TEI HTTP 调用。
  • 读取问题与正文，重新判断相关性。
  • 请求分批，遇 413/429 减半重试。
  • 模型在独立服务中驻留，不是 Python __new__ 单例。

Embedding 也支持自适应降批。429 表示限流或过载，不能仅凭状态码判断为 token 超限；降至单条仍失败会抛错，不保证所有输入都能恢复。

04 · 混合检索如何融合

向量 Top40 ─┐
关键词 Top30 ├→ RRF 合并 → Top50 → PostgreSQL 回表取正文与鉴权
图谱 Top30 ─┘
  → reranker 精排 → 上下文筛选 → 证据门 → LLM 生成

第一层：RRF 按排名融合

三路结果统一为 chunk_id 与原始分数；按 ID 去重合并，跨路累计排名贡献。同一路重复 ID 不重复计分。三路当前等权。

RRF(d) = Σ 1 / (60 + rank_s(d))
排名从 1 开始；该路未命中贡献 0。
原始相似度分数用于追踪，不直接相加。
教学示例：非真实运行数据
候选向量排名关键词排名图谱排名RRF
A13未命中1/61 + 1/63 ≈ 0.03227
B2121/62 + 1/61 + 1/62 ≈ 0.04865
C未命中未命中11/61 ≈ 0.01639

排序为 B → A → C：多路共同支持的候选得到更多贡献。RRF 分数不是正确率。

第二层：重排重新判断相关性

融合后先取默认前 50 个候选，再回数据库剔除无权访问或非当前版本的结果。reranker 读取正文打分并排序，当前不再将 RRF 与 rerank 分数加权相加。

第三层：选择证据

  • 默认最多 10 个 chunk；比较类最多 12 个；每篇文档最多 4 个。
  • 按去空白后的正文精确去重；摘要优先不同章节，比较优先不同文档。
  • 表格类对表格候选做 0.05 的轻量排序加分。
  • 证据门检查所选上下文前 3 条可用分数：默认最高值 ≥0.5、均值 ≥0.375，并检查问题数字/编号覆盖。
  • 召回一致性会记录，但不是当前 sufficient 判定的硬条件。
  • 重排失败保留 RRF 排序，但缺少重排分数通常导致保守拒答。

依据：app/retrieval.py、app/query.py、app/config.py。

05 · Agent 编排与后台 Worker

当前采用固定工作流，不是 Self-RAG 反思循环，也不是模型自主规划和选择工具的多智能体系统。

授权 → 规则分类 → 问题空白规范化 → 三路并行召回
→ 融合 → 重排 → 上下文 → 证据门 → 可选外部搜索
→ 生成 → 引用校验 → 持久化答案与事件 → SSE读取
  • 路由：按关键词选择 compare / graph / table / latest / summary / fact。
  • 问题改写：当前仅规范化空白，不生成假设文档；HyDE 只有配置开关。
  • 任务消费：Worker 轮询 QueryRun、IngestJob、SyncOutbox、EvalRun，使用 advisory lock 避免重复执行。
  • 阶段恢复：导入从持久业务阶段恢复，可重试错误按退避策略处理。
  • 一致性：巡检外部索引 ID 与数据库差异，创建补偿任务。
  • 取消：阶段边界检查；已经发出的外部请求可能等待超时。
  • 观测：JobStep、timings 和 run.stage 记录状态与阶段耗时。

单个 Worker 逐项执行任务，问答图的三路召回内部并行。独立 API 保持响应，但长任务仍可能占用 Worker；当前没有分级任务池或通用公平调度。

06 · 双模式回答与持久 SSE

事实类：逐字证据

模型输出 claims 与 chunk_ids，每句须逐字存在于其引用证据中，否则拒绝输出该答案。

摘要 / 比较类：归纳生成

允许组织归纳语言，检查引用来源与数字出现。不是完整语义真实性验证，不能保证因果、实体关系等都正确。

  • 通过 OpenAI-compatible /chat/completions 调用配置的单个模型端点；此前本机接入 DeepSeek。
  • 会话历史保存在 PostgreSQL，但当前生成调用只传当前问题与所选证据。
  • 答案、引用快照、完成状态和事件在事务内提交。
  • 引用包含文档、版本、页码、章节、chunk 和摘录。
  • SSE 支持 run.started / run.stage / citation.ready / answer.delta / answer.replace / run.completed / run.failed。
  • 使用递增 sequence 和 Last-Event-ID 重放，前端增量解析 SSE。

当前是校验后分段输出，不是原始模型 token 实时透传。每文档最多 4 个片段的限制仍适用于摘要，因此不等于全文覆盖总结。也没有三层记忆注入或自动上下文压缩。

07 · 知识图谱

  • 节点：Document、Chunk、Entity、Alias。
  • 关系：PART_OF、MENTIONS、SUPPORTED_BY、RELATES_TO、NEXT_CHUNK。
  • 抽取：规则识别显式实体、别名及明确关系格式，没有通用 LLM 抽实体。
  • 归并：实体 ID 对知识库 ID 与小写名称做哈希，结合租户隔离；同名实体可跨文档归并。
  • 类型边界：ID 不是 name|type，同名不同类型不会因此自动拆分。
  • 检索：实体/别名字符串匹配 + Cypher 最多 2 跳扩展，返回支撑 chunk。
  • 权限：节点、路径关系和来源 chunk 均受范围、版本与 ACL 约束。

没有 NetworkX、vis-network 图谱页面、top-200 渐进披露或邻接展开接口。关系链未作为独立材料直接注入回答，图谱主要辅助召回证据。

08 · 持久化与安全

  • 唯一业务事实源：PostgreSQL 保存文件 Blob、解析结构、正文、任务、消息、引用、事件、评测和审计。
  • 认证：PBKDF2-SHA256 加盐密码哈希 + JWT，校验有效用户与 KB membership。
  • 隔离：显式租户过滤、RLS、复合外键、索引 ACL、最终回表鉴权。
  • 幂等：关键接口 Idempotency-Key；Blob 内容哈希去重；稳定 ID upsert 外部索引。
  • 发布：新版本双索引同步完成后才切换 current_version_id；此前保留旧版本可查询。
  • 删除：通过 Outbox 补偿删除外部索引；硬删除还清理相关正文与历史答案/引用快照。
  • Redis：可选短期限流，不承担持久任务队列、会话事实源或记忆系统。

09 · 评测与验证边界

实现评测运行器、结果持久化、Badcase 标签与可选 RAGAS 接口。支持 Recall@10、MRR@10、Context Precision、引用精确率、拒答正确性、字符准确率及结构 F1 等计算。

仓库评测集当前只有 3 条 fixture，报告标记 fixture_only=true、quality_claim_allowed=false。手工预测输入的满分不能用于宣称真实检索质量、OCR 准确率或 RAGAS 达标。

此前本机会话验证过 38 个 chunk 的降批向量化、40 候选分批重排和 132 个 chunk 文档入库。这是历史单样本记录，不代表当前服务在线，也不是总体成功率、并发或吞吐成绩。

依据：app/evaluation.py、eval/reports/latest.json、docs/evaluation.md。旧文档可能早于近期改动，功能判断优先当前代码。

12 · 未实现能力与参考项目差异

参考功能当前项目
Self-RAG 反思循环未实现；固定流程 + 一次证据门，没有反思改写后循环检索。
三层记忆 / 200k 自动压缩未实现；会话持久化不等于历史注入，无中长期记忆与压缩审计。
SKILL.md 技能系统业务应用无扫描、CRUD 或渐进注入；开发工具的技能不属于业务能力。
LLM 抽实体、模糊匹配、3 跳 BFS规则抽取 + 字符串匹配 + Neo4j 最多 2 跳路径。
BM25、加权 RRF、HyDEjieba + BM25、等权 RRF；HyDE 未接入执行。
四家独立模型 provider单个 OpenAI-compatible 端点，无在线多模型配置管理 UI。
MCP 网络问答双开关受控调用，外部结果尚未整合进可验证答案。
完整视觉多模态多格式解析到文本及结构，不承诺图片语义或曲线趋势理解。
生产质量与规模达标需人工标注、基线对比、并发压测与恢复演练，不能由样例推断。

13 · 本机运行入口

用于已有本地配置的环境；新环境仍需准备数据库、账号、模型文件与 checkpoint。本页不会执行命令。

# 项目根目录；依赖已配置
 docker compose -f compose.dependencies.yaml up -d
 powershell -ExecutionPolicy Bypass -File scripts/start_mineru.ps1
 powershell -ExecutionPolicy Bypass -File scripts/start_local.ps1

# Worker 独立运行
 $demo = Get-Content .runtime/demo.json | ConvertFrom-Json
 .\.venv\Scripts\python.exe -m app.worker --tenant $demo.tenant_id

工作台：http://127.0.0.1:8000/ · API：/docs · 数据库就绪：/health/ready

start_local.ps1 不统一启动全部依赖和 Worker，且可能复用已运行的 API。数据库健康检查成功不代表所有模型、索引和 Worker 正常。容器与本机的服务地址需分别配置。
