③链路一 · 文档导入 / 知识入库

入口 POST /api/v1/kbs/{kb_id}/documents（需 Idempotency-Key）。API 只做校验、去重、建任务；耗时工作全部在 Worker 内，由 LangGraph 13 阶段图驱动，检查点落在 PG workflow schema，崩溃后可从当前阶段幂等续跑。

PG 事务 外部服务调用 发布/终点
上传+validate_file→ save_blob(SHA256去重)→ 建 Document/Version/Job

—— Worker 消费 IngestJob，LangGraph 13 阶段（每阶段落 JobStep/状态，幂等）——

validate_file→ scan_file(ClamAV)→ persist_document→ normalize_file→ parse_with_mineru→ validate_parse_quality→ build_outline→ create_chunks
generate_embeddings→ sync_milvus→ extract_entities→ sync_neo4j→ publish_version→ cleanup → READY

关键设计：chunk 与两类 Outbox（milvus/neo4j）同事务写入 → 外部调用完成后提交 DONE 收据；publish_version 原子门要求「质量 PASS/WARN + 非空 chunk + Milvus&Neo4j 收据全 DONE」才切换 current_version_id。reconciler 每 60s 比对 ID 集合，漂移超 15 分钟告警并生成补偿。

④链路二 · 智能问答 / 证据检索

入口 POST /api/v1/chat/runs → 创建持久 QueryRun + 用户消息 + run.started。Worker 走 LangGraph 15 节点图；前端通过 SSE（Last-Event-ID 重放）订阅增量事件。

生成采用严格逐字摘录模式：每句必须逐字存在于所有引用证据中，代码级校验通过才发 answer.delta，否则拒答（INSUFFICIENT_EVIDENCE）。引用为不可漂移快照（document_id/version/chunk_id/页码/章节/摘录）。权限在 API、PG 显式条件+RLS、Milvus 标量、Cypher、最终回表五处一致校验。
