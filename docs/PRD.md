# 产品与业务需求解析

> 本文从现有实现提炼需求，不代表所有理想功能已落地。解析日期：2026-10-19。

## 产品目标

让采购与仓储人员通过业务页面或自然语言完成查询、分析与受控操作，同时保留角色职责、正式审批和可追踪业务记录。主要对象为摩托车零配件的供应商、物料、采购单和库存。

## 用户与权限

| 角色 | 可用能力 | 主要约束 |
| --- | --- | --- |
| 采购员 | 采购申请 / 订单、供应商和库存查询、智能助手 | 不能正式审批、收货或调整库存 |
| 仓管员 | 库存、收货、领料 / 退库 / 盘点、采购只读、智能助手 | 不能提交采购或正式审批 |
| 审批人 | 采购与仓库业务、正式审批、主数据维护 | 禁止本人审批自己创建的业务 |
| 管理员 | 上述能力与账号管理 | 同样禁止自审；系统保护最后一个管理员 |

## 核心场景与验收依据

### 查询与分析

用户查询供应商、物料、订单、库存预警或当天收货。结果必须来源于当前业务接口，空记录与错误不能伪装成有数据；日期 / 数量 / 单位口径应清楚。本地图表可作为结果展示，报表下载为附加交付。

### 自然语言采购

用户提供不完整需求，系统查验供应商与物料、补全缺失字段、展示确认内容；确认后重新核验准入，再提交并读回记录。拒绝不写入，未知结果保留核验入口；模型不能伪造操作人或跳过角色限制。

### 正式审批

直接订单先进入待审核，由其他审批人批准；采购申请通过后生成已审核订单。审批页面应使用当前版本，防止过期内容被批准。人工执行确认不替代这一步。

### 收货与库存作业

仓管员记录送货批次、验收与拒收；只有合格数量入库。领料检查领料人和可用库存，盘点检查账面快照，库存变更保存原因和流水。重复请求应返回原结果或明确冲突，不能重复增加库存。

### 登录和会话

首次初始化管理员只允许一次。不同账号及不同标签页按服务器身份访问各自会话；退出 / 停用 / 改密后撤销会话。刷新页面应能读取待处理中断；历史匿名数据不自动归属新账号。

## 当前非功能约束

- MySQL 保存业务事实，PostgreSQL 支持完整 Agent 状态和展示历史。
- Web API 以单进程会话互斥为基础；当前不承诺多副本恢复一致性。
- 离线回归、真实数据库测试、真实模型评测和浏览器验收分别报告。
- 部署需要自行配置 TLS、入口域名、持久卷与备份；登录机制不是生产运维完成证明。

## 不在本次已实现范围内

完整财务结算、生产计划、多仓调拨平台、销售全链路、向量 RAG / 知识图谱、自动多模型备援、分布式锁与跨库事务均不作为当前交付能力。

## 演示建议

先在空演示库建立供应商与物料，创建采购员、仓管员和另一位审批人。展示“查库存 → 提采购 → 查看执行确认 → 正式审批 → 收货 → 查流水”，再展示拒绝、越权、自审和过期确认被阻止。真实模型演示前先验证模型连通性，不用历史测试统计替代现场验证。
