按参考仓库的文档层次建立 README、项目总结、快速开始、架构、PRD 与计划；用源码更正旧文档中的匿名身份、9 个 MCP 工具、任意 shell、完全内存运行等描述。建立排除真实数据和运行内容的发布副本，记录本次实际测试证据。

## 优先级 1：运行可复现与真实链路

1. 固定 Python 依赖与镜像版本，建立可重建环境；验收为干净环境安装与离线回归通过。
2. 补齐容器应用账号初始化与认证变量透传，重新验证六服务启动、登录与持久化；验收不能仅凭 Compose 静态解析。
3. 为黑盒评测框架补充当前登录会话与角色驱动，更新旧数据集；在独立数据库执行真实模型端到端评测，保留失败记录。
4. 单独跑真实 MySQL 并发 / 事务与 PostgreSQL 重启恢复用例，明确测试数据库和清理范围。

## 优先级 2：交互与运行质量

1. 对生产前端拆包，降低首次加载体积；目前单一 JS chunk 超过 Vite 提示阈值。
2. 对真实浏览器的登录、角色切换、表单、SSE 中断和刷新恢复建立验收，而不是只依赖组件 Mock。
3. 处理当前依赖废弃与 Pydantic 序列化告警，防止升级后协议变化。
4. 补齐请求链路标识、错误分类与恢复指引，观测 Web → MCP → ERP 的失败位置。

## 优先级 3：一致性与扩展

1. 若需多实例部署，引入跨进程会话协调，并验证恢复请求竞争与重复提交。
2. 明确业务提交和身份审计之间的失败补偿，保留“先核验再重试”的语义。
3. 评估订单历史主数据快照，避免当前供应商 / 物料变更影响历史展示。
4. 补全技能删除同步和生命周期；任意脚本执行仍需单独设计隔离及权限，不直接重新开放。

没有本次实测的吞吐量、延迟、业务成功率或上线日期，本文不设置虚构指标。
